Detailed timeline

STARTED BIP-110
~Dec 1, 2025 -- ~Aug 7, 2026
Blocks 889,056 -- 961,631
Voluntary signaling period. Miners can set version bit 4 to signal support for BIP-110. No blocks are rejected. No rules enforced. This is just counting support.
Mandatory Signaling BIP-110
~Aug 7 -- ~Aug 21, 2026
Blocks 961,632 -- 963,647
First confrontation point. Every block must set version bit 4 or it is rejected by BIP-110 nodes. Bitcoin Core does not set this bit, so all unmodified Core blocks are rejected. The fork trigger is the block header, not transaction content.
Miners must choose: set the bit (one header bit, zero protocol cost) or risk having blocks orphaned. The actual data filtering rules are not enforced yet.
eCash Hard Fork eCash
Aug 21, 2026 at 15:00 UTC
Target block ~964,000
Bitcoin chain splits. eCash forks off with Drivechains (BIP-300/301) enabled and 7 sidechains at launch. Every BTC holder receives eCash 1:1 on fork day. This is a hard fork -- a permanent, incompatible chain split.
Timed to land right after BIP-110's mandatory signaling period, during the LOCKED_IN transition. By LayerTwo Labs.
LOCKED_IN BIP-110
~Aug 21 -- ~Sep 4, 2026
Blocks 963,648 -- 965,663
Quiet transition. Mandatory signaling has ended, transaction filtering has not yet started. No blocks are rejected by BIP-110 nodes. Miners have ~2 weeks to prepare for active enforcement.
The eCash fork (block ~964,000) lands during this window. BIP-110 activation is guaranteed regardless of signaling results -- the code forces LOCKED_IN at this height.
ACTIVE BIP-110
~Sep 4, 2026 -- ~Sep 3, 2027
Blocks 965,664 -- 1,018,079
Transaction filtering enforced. BIP-110's 7 heuristics are now consensus rules. Blocks with oversized OP_RETURN, inscriptions, banned opcodes, or other violating data are rejected. The fork trigger is now transaction content, not software version -- any software producing clean blocks is fine.
EXPIRED BIP-110
~Sep 3, 2027+
Block 1,018,080+
All rules dropped. BIP-110 auto-expires and the network returns to status quo. This is the "Temporary" in "Reduced Data Temporary Softfork." If the community wants to continue filtering, a new deployment would be needed.
